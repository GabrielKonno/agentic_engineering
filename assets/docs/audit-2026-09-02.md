## Meta-observation

The 2026-08-31 run named the recurring class as *"a fix applied to the instance the report named,
without sweeping the class"* and answered it with checklist item 4. This run shows item 4 is
necessary and not sufficient, in two distinct ways:

1. **Item 4 has no per-fix receipt.** It mandates a report — `class sweep: N directions checked, M
   extra instances found` — but that is ONE aggregate line for a whole session. The applying
   session emitted `4 directions, 3 extra instances` in good faith and still missed seven,
   because a single aggregate cannot be wrong per fix. Compare the discipline the framework
   already applies elsewhere: `autonomous-loop`'s task-closure check runs at EVERY task boundary,
   not once per session.
2. **Nothing verifies that a correction LANDED.** Five of this run's HIGH/MEDIUM findings are
   defects the fixes themselves introduced (J-1..J-4, J-6, J-7). Every one passes a "is the
   required text present?" check; only reading the surrounding structure finds them. Audit intake
   step 2 mandates re-verifying a finding BEFORE applying it and nothing AFTER.

Both gaps are instances of J-16: the verification pass exists as a practice and not as an
instruction. Writing it down is the single highest-leverage fix in this report.

**Suggestion:** Run `/maintenance` to apply fixes, using this report as the correction plan.
Group 1 first — those are regressions currently on `main`.
